# relaycheck：方法、统计与校准

[English](METHOD.md) · [简体中文](METHOD.zh-CN.md)

本文说明 relaycheck 测什么、怎么判定、判定在真实数据上校准得如何，以及有哪些情况测不出来。下面所有数字都来自可以复现的实验（见[复现](#复现)）。relaycheck 给出的是**证据，不是铁证**。

## 1. 威胁模型

relaycheck 站在付费用户一边。用户通过中转（代理、网关、二道贩子）调用模型，想知道对方给的是不是宣称的那个模型。中转能控制你和上游之间的每一个字节。我们考虑以下几种情况：

| 威胁 | 中转的做法 | 对应探针组 |
|---|---|---|
| **换模型** | 用更便宜或别的模型冒充所请求的模型，并改写响应里的 `model` 字段 | 身份（统计指纹）。protocol 的 `model_echo` 只能抓到粗心的中转 |
| **量化版、旧版或微调版** | 同一家族但权重不同，例如量化后的开源模型或上一个快照 | 身份。检出率取决于回答分布偏移了多少（见 §5.3） |
| **隐藏提示注入并按量计费** | 每次请求偷偷加系统提示或指令，多出来的 input token 算在你头上 | 计费 `hidden_tokens`（精确基准），身份 `tokenizer` |
| **缓存计费造假** | 不报缓存命中（按全价收费），或凭空报命中 | 计费 `prompt_cache` |
| **截断上下文** | 为省成本悄悄丢掉长提示的开头、结尾或中段 | 上下文（在 10/50/90% 深度埋针；2k 对照、32k，`--deep` 加测 100k） |
| **协议不保真** | 丢弃工具定义或工具结果、SSE 流不完整、忽略 `stop`/`max_tokens`、剥掉 thinking 签名 | 协议 |

不在防御范围内：**专门针对 relaycheck 的中转**，即识别出我们的固定提示后只把这些请求转给真模型。探针都是普通的短请求，但铁了心的对手仍能认出来。见 §7。

## 2. 身份：统计指纹

### 2.1 探针（探针集 v2）

探针是在 `temperature=1` 下提问的有限选项问题，例如 *"Pick a name for a kitten: Luna, Milo, Oliver, Leo, Bella, Max. Reply with only your choice, nothing else."* 一个模型在一组固定探针上的回答频率就是它的行为指纹。不同模型、同一模型的不同快照，偏好的答案都不一样。

**v2 探针集**（relaycheck 0.2）共 **24 个探针**，从 **46 个候选**里选出。候选在 gpt-6-luna、gpt-5.6-luna、gpt-5-nano、gpt-5.4-nano 上各采样 20 次做了筛选，共 3,839 次请求：

- **去掉**了所有被测模型答案都一样、因而不含信息的 v1 探针：数字→7、颜色→蓝、字母→C、水果→芒果、1–5→3、方向→北、硬币→正面、乐器→钢琴、宝石→蓝宝石。在所有模型上都确定的新候选（1–10→7、棋子→马、城市→东京、鸟→猫头鹰、天气→晴等）也没有加入。
- **保留**两类探针：一类在 gpt-6-luna 上分布分散（熵高，如 `letter10`、`zh_animal`、`continent`、`month`、`metal`、`coin3`）；另一类即使一方几乎确定，也能把 gpt-6-luna 和**同家族**模型分开（`catname` Milo 对 Luna、`animal_rev` 狐狸对猫头鹰、`planet` 火星对地球、`digit_not7` 4 对 3，以及 `flower`、`tree`、`dessert`）。
- 加入两道中文探针（`zh_animal`、`zh_color`）和一道带单词别名的探针（`card_rank`：“Ace”“Queen”等）。

新的 100 样本 gpt-6-luna 参考里，24 个探针只有 1 个是确定的（`card_rank`→7），v1 是 16 个里有 6 个。真实运行中 24 个探针里有 23 个提供信息。

选择偏差：探针是在筛选数据上挑出来的，筛选数据会高估区分度。§5 的所有检出率都来自选定探针**之后**新采集的样本。

### 2.2 答案归一化

`classify()`（src/probes/classify.ts）把自由文本映射到选项标签：

- 做 NFKC 归一（全角 `７` 变成 `7`），转小写，去掉 markdown、引号和末尾标点，去掉“I'd pick”“Answer:”“我选”之类的开头。
- 去掉某些中转泄露的 `<think>…</think>` 块。**未闭合**的 `<think>` 表示还没给出答案，记为 `other`。
- 支持数字词（`seven`、`七`）和每个探针的别名（`fall`→autumn、`蓝`↔`blue`、`Ace`→`A`）。
- 单字符标签（字母、数字）只按独立 token 匹配，并先去掉英文缩写。0.1 版会把 “I'd go with C” 记成 **D**，把 “a C” 记成 **A**。同时出现两个不同单字符标签的回答记为 `other`，只是碰巧含有某个字母的长段文字也记为 `other`。
- 中日韩文字没有词边界，CJK 标签按子串匹配。
- 其余回答归为 `other` 类，和其他答案一样参与检验，因为不守格式本身就是信号。

### 2.3 单探针检验

每个探针得到一张 2 × K 列联表：被测这次运行的计数（默认 n = 24）对参考计数（默认 100）。统计量是 Pearson 齐性卡方。p 值是**蒙特卡洛置换 p 值**：把两边的回答合并，再随机按原大小重新分组，边际固定，与 Fisher–Freeman–Halton 精确检验相同。这种方法对任意样本量、任意稀疏程度都有效，也计入了参考本身的抽样误差。

- **序贯停止**（Besag & Clifford 1991）：模拟到有 40 个模拟统计量达到观测值、或满 20,000 张表时停止。如果一个都没达到，再加 200,000 张表压低下限。这样强信号算得快，弱信号也算得准。
- **mid-p**：与观测统计量打平的表只算一半。回答分布接近独热时，卡方统计量高度离散，普通 p 值会非常保守（§4.1）。
- **下限与渐近尾部**：没有模拟表达到观测值时，p 值取蒙特卡洛下限 1/(L+1)。只有在表格足够稠密时（Cochran 准则：所有期望计数 ≥ 1，且至少 80% ≥ 5），才在下限以下使用卡方渐近尾部。0.1 版只要蒙特卡洛碰到下限就用渐近尾部，而稀疏表的渐近尾部严重偏激进。
- df = 0 的探针（双方都只给出同一个答案）不含证据，直接丢弃。

### 2.4 过离散校正

真实端点的回答并不完全独立。我们采集了 20 个时间块 × 24 次官方 gpt-6-luna 样本（每个探针，见 §4.2）。块与块之间计数的波动比多项分布允许的更大，合并后的离散度为 **φ̂ = Σχ²/Σdf = 1.098**（Σdf = 836，渐近 p = 0.025）。可能的原因是批处理和不同服务副本。

这个值看起来小，影响却不小。模拟中，φ = 1.1 时如果不校正，存疑级误报率翻倍到 1.95%；φ = 1.3 时不一致级误报率升高 5.5 倍，到 0.55%（§4.1）。所以 relaycheck 把每个探针的卡方除以 max(1, φ)，即准似然校正。φ 存在参考文件里：

- `relaycheck fingerprint` 分 4 个交错时间块采样参考，并保存块间估计；
- `refs/gpt-6-luna.json` 中 φ = 1.098，由额外采集的 20 个官方时间块估计。

上限为 2。校正会让检验略偏保守，因为打平的表此时算作超过。

### 2.5 合并与判定

各探针 p 值用 **Cauchy 组合检验**（Liu & Xie 2020）合并：T = Σ wᵢ tan((0.5 − pᵢ)π)，权重相等，pᵢ 截断在 0.99。它对探针之间的相关性稳健，结果由最强的信号主导。24 个探针中只要有一个落在蒙特卡洛下限（5·10⁻⁶），就足以判为不一致。

| 合并 p | 身份结论 |
|---|---|
| < 0.001 | **不一致（fail）**：回答分布与参考不同 |
| < 0.01 | **存疑（warn）**：轻微偏离，建议加大 `--samples` 复测 |
| 其他 | **一致（pass）** |

如果判为一致，但超过 20% 的采样请求失败，结论降为存疑。失败的请求不计入计数。中转若只对某些答案报错会让检验有偏，所以报告里会给出错误率。

### 2.6 参考兼容性

参考文件现在会记录 `probeSetVersion`、`sampling`（协议、温度、max tokens、reasoning effort）、`dispersion` 和 `billing` 基准。检测时：

- **拒绝**未知版本的探针集，也拒绝提示词与该版本定义不一致的参考（被改过或来自别的工具）；
- **接受**旧的 v1 参考，按它自己版本的探针定义比较，同时提示区分力较弱；
- reasoning effort 与参考不一致时给出**存疑**，因为 effort 不同确实会改变回答分布，有误报风险。协议不同（Chat 对 Responses）只作提示。

### 2.7 启发式检查（除注明外不参与判定）

- 自报身份（“你是哪个模型？”）默认只作参考（info）；只有说出**其他厂商**的家族名时才存疑（warn）。官方 gpt-6-luna 自称 “GPT-5.2 Thinking”，gpt-5.6-luna 自称 “OpenAI o3”。同一厂商、只是说错名字的自报不应让老实的中转被判为存疑。
- 知识截止日期只作参考。
- **分词器**检查把一段固定的混合文字计费的 input token 数，与参考里存的官方计数对比。

## 3. 计费

### 3.1 隐藏注入 token：精确基准

0.1 版在 OpenAI 侧用约 4 字符/token 的估算对比 `usage.input_tokens`，只能看出约 200 token 以上的注入。0.2 版改为精确比对：

- 生成指纹时，向**可信**端点发送 4 条固定提示（同一段文字的 3 种长度，外加分词器文本），每条发两次，按协议保存官方 `usage.input_tokens`；两次不一致就拒绝保存。OpenAI 端点会同时测 Chat Completions 和 Responses。gpt-6-luna 两种协议的计数完全相同：b1 = 80、b4 = 257、b12 = 729、tokenizer = 74。
- 检测时向中转发送同样的提示，与基准比对：
  - 所有差值的绝对值 < 4 → **一致**（“逐 token 一致”）；
  - 各长度差值相同（波动 ≤ max(3, 2%)）→ 每请求固定注入：≥ 16 token 判**不一致**，4–15 判**存疑**；
  - 差值随提示长度增长（斜率 ≠ 1）→ **存疑**：分词器不同，很可能是别的模型家族；
  - 计费比官方少 → **存疑**：提示被改写或截断。
- 只有当参考对应同一模型、协议一致、提示哈希一致时才使用基准。否则回退到 Anthropic `count_tokens`（精确）或本地估算，并在报告里标为**未校准**。Anthropic 参考也会记录同样的基准，覆盖那些不提供 `count_tokens` 的中转。

真实检测：官方 API 三条提示的差值全部为 0。一个每次在请求前加 37 个词隐藏系统提示的本地中转被抓到，见 §5.4。

### 3.2 提示缓存

检查会把一段约 5k token、带全新随机会话 id 的前缀发送两次。第二次没有命中时，隔 1.5 秒再发第三次，因为 OpenAI 缓存是尽力而为的，受路由影响。判定规则：

- 一直没有命中 → 存疑；
- 一个从未出现过的随机前缀在**第一次**请求就报告命中 → 存疑，缓存数据不可信；
- 缓存 token 多于提示 token → 不一致；
- Anthropic：命中缓存但 `input_tokens` 仍是全量 → 不一致（重复计费）。

官方 gpt-6-luna 第二次请求读到 3,810 个缓存 token，约占提示的 76%。

## 4. 校准：误报率

### 4.1 模拟（不调用 API）

`scripts/calibrate-sim.ts` 在模拟数据上运行实际发布的打分代码：参考 ~ Mult(100, P)，分 4 块；被测 ~ Mult(24, P)。除另有说明外，P 取真实 gpt-6-luna 参考。括号内是精确的 95% Clopper–Pearson 区间。名义水平为 0.1%（不一致）和 1%（存疑）。

| 设置 | 模拟次数 | p < 0.001（不一致） | p < 0.01（存疑及以上） | p < 0.05 |
|---|---|---|---|---|
| **发布配置**：置换 + mid-p + φ 校正，数据 φ = 1.098 | 4,000 | **0.050%** [0.006, 0.18] | **0.80%** [0.55, 1.13] | 2.6% |
| 置换 + mid-p，独立数据（φ = 1） | 10,000 | 0.040% [0.011, 0.10] | 0.87% [0.70, 1.07] | 4.4% |
| 同上，稀疏随机真值（Dirichlet α = 0.3） | 5,000 | 0.060% [0.012, 0.18] | 0.80% [0.57, 1.09] | 4.4% |
| 同上，以 v1 参考为真值 | 10,000 | 0.040% [0.011, 0.10] | 0.61% [0.47, 0.78] | 4.1% |
| 同上，每探针 n = 12 | 2,500 | 0.080% [0.010, 0.29] | 1.24% [0.84, 1.75] | 4.6% |
| 发布配置，n = 12 | 2,000 | 0.000% [0, 0.18] | 0.45% [0.21, 0.85] | 1.5% |
| 置换 + mid-p，n = 48 | 2,500 | 0.040% [0.001, 0.22] | 0.88% [0.55, 1.33] | 4.4% |
| 置换但**不用** mid-p（严格保守），v1 真值 | 10,000 | 0.000% [0, 0.037] | 0.24% | 1.2% |
| 过离散 φ = 1.1，**不**校正 | 4,000 | 0.050% | **1.95%** [1.54, 2.43] | 8.2% |
| 过离散 φ = 1.1，校正 | 4,000 | 0.025% | 0.70% | 2.9% |
| 过离散 φ = 1.3，**不**校正 | 4,000 | **0.55%** [0.35, 0.83] | 4.20% | 18.2% |
| 过离散 φ = 1.3，校正 | 4,000 | 0.175% [0.07, 0.36] | 1.27% | 4.1% |
| 0.1 版方法（参数自助法），稀疏真值 | 4,000 | 0.10% | 1.15% | 5.6% |

结论：

- 默认 24 次采样时，发布配置的误报率不超过名义水平。
- mid-p 是必要的。不用它，检验会浪费大部分检验水平和检出力。
- 过离散校正是让真实端点误报率保持在名义水平的关键。
- 12 次采样且不做校正时，存疑级误报率略高于名义水平（1.24%）；用发布配置（含校正）时为 0.45%，不一致级为 0%（2,000 次模拟）。

### 4.2 真实误报实验（官方 gpt-6-luna）

- **参考**：`refs/gpt-6-luna.json`，探针集 v2，经官方 Responses API（`--reasoning-effort none`）每探针 100 样本 × 24 个探针，共 2,416 次请求。
- **零假设运行**：20 次独立的仅身份检测，每次 24 次采样 × 24 个探针，共 **11,520 次请求**。这些数据在参考之后采集，像真实 CLI 运行一样按时间交错，并完全按 CLI 的方式打分（`scripts/analyze-real.ts`）。

| | 不一致（p < 0.001） | 存疑（p < 0.01） | 一致 | 最小 p | p 中位数 |
|---|---|---|---|---|---|
| 发布配置（φ = 1.098） | **0 / 20** | **0 / 20** | 20 / 20 | 0.105 | 0.93 |
| 不做过离散校正 | 0 / 20 | 0 / 20 | 20 / 20 | 0.031 | 0.27 |

- 0 / 20 对真实误报率的约束很宽：95% 上界为 13.9%。精度主要由上面的模拟提供。
- 探针级 480 次检验中，校正后 5.6% 低于 0.05，0.4% 低于 0.01，没有低于 0.001 的（不校正时分别为 6.9%、1.7%、0）。
- 另外两次官方运行：全组 CLI 检查（含 `--deep`）p = 0.722；20 样本的筛选批次 p = 0.95。
- **漂移检查**：每个探针合并的 480 个新样本对比 100 样本参考，24 个探针中最低 p = 0.02。在实验的约一小时内没有漂移证据。这段时间的 φ 估计为 1.098；只有 `flower` 一个探针显示显著的块内聚集（置换 p = 0.009）。

## 5. 检出力：抓住别的模型

### 5.1 真实运行：其他模型冒充 gpt-6-luna

对每个模型新采集样本，对照 gpt-6-luna 参考打分，每次运行 24 次采样 × 24 个探针：

| 实际服务的模型 | 运行次数 | 判为不一致 | 合并 p（中位数，最大值） | 差异最大的探针 |
|---|---|---|---|---|
| gpt-5.6-luna（同家族） | 10 | **10 / 10** | 6.9·10⁻¹⁵，2.6·10⁻¹⁴ | planet、digit_not7、catname |
| gpt-5-nano | 5 | **5 / 5** | 1.8·10⁻¹⁸，1.7·10⁻¹⁴ | tree、planet、shape、animal_rev |
| gpt-5.4-nano | 5 | **5 / 5** | 4.2·10⁻¹⁷，1.9·10⁻¹⁶ | daytime、animal_rev、flower、catname |

CLI 端到端：本地一个不老实的中转收到 `model=gpt-6-luna`，向上游调用 gpt-5.6-luna，再把 `model` 字段改回 gpt-6-luna。relaycheck 报告**不一致，p = 7.2·10⁻¹⁵**，退出码 1。协议、计费（分词器相同，token 数逐个一致）、提示缓存、32k 上下文全部通过，`model` 回显也正确。只有指纹抓到了换模型。

### 5.2 部分替换（模拟）

模拟一个中转：以比例 *w* 转发真模型，其余转发 gpt-5.6-luna，两者都用真实回答分布。采用发布配置，每格 500 次模拟，蒙特卡洛下限 5·10⁻⁵（只会低估检出力）：

| 真货比例 w | 0 | 0.5 | 0.7 | 0.8 | 0.9 |
|---|---|---|---|---|---|
| 判为不一致的概率（24 次采样） | 100% | 99.6% | 44.6% | 7.8% | 0.2% |
| 存疑或不一致的概率 | 100% | 100% | 93.6% | 55.2% | 9.2% |

其他替代模型，同样的模拟。每格为“判为不一致的概率 / 存疑或不一致的概率”，24 次采样：

| 替代模型 | w = 0 | 0.5 | 0.7 | 0.8 | 0.9 |
|---|---|---|---|---|---|
| gpt-5.6-luna | 100 / 100% | 99.6 / 100% | 44.6 / 93.6% | 7.8 / 55.2% | 0.2 / 9.2% |
| gpt-5-nano | 100 / 100% | 100 / 100% | 99.4 / 100% | 59.8 / 98.4% | 1.8 / 35.2% |
| gpt-5.4-nano | 100 / 100% | 100 / 100% | 85.0 / 99.6% | 25.0 / 83.4% | 1.0 / 19.6% |

每探针采样数的影响（替代模型 gpt-5.6-luna）。每格为“判为不一致的概率 / 存疑或不一致的概率”：

| `--samples` | 6 | 12 | 24（默认） | 48 |
|---|---|---|---|---|
| 完全替换（w = 0） | 100 / 100% | 100 / 100% | 100 / 100% | 100 / 100% |
| 80% 真货（w = 0.8） | 0 / 12.0% | 1.0 / 25.2% | 7.8 / 55.2% | 26.4 / 77.0% |

完全换成这三个模型中的任何一个，每探针 6 次采样就能抓到。部分替换则需要多得多的样本。

### 5.3 检出力从哪里来

检出力来自两个模型最偏好答案不同的探针。同家族模型之间不同的探针比不同家族少，但 gpt-5.6-luna 与 gpt-6-luna 有好几个探针完全翻转（火星→地球、Milo→Luna、4→3），单次运行就足以判定。对**同一套权重**做量化，通常只会让概率轻微移动，效应量小，就像 w ≈ 0.8–0.9 那几列，需要更大的 `--samples`。

### 5.4 隐藏提示注入（真实）

在官方 API 前面放一个本地代理，每次给 gpt-6-luna 请求加一段 37 个词的隐藏系统指令。relaycheck（`--probes identity,billing`）报告**不一致：每请求多计 37 个 input token**。三条基准提示的差值相同，检查正是据此区分“每请求固定注入”和“分词器不同”。分词器检查显示计费 111 个 token，官方为 74 个。身份指纹也偏移到 p = 0.001（存疑）：隐藏指令同样会改变回答分布，主要体现在 `sport` 和 `metal` 两个探针上。

## 6. 上下文探针

每份文档在 10%、50%、90% 深度各藏一个口令。只保留开头、只保留结尾、去掉中段（middle-out）这几种截断都会丢掉至少一个。文档大小为 2k（对照）、32k，以及 `--deep` 时的 100k（约 4 字符/token 的近似值）。匹配时容忍大小写、markdown 和 Unicode 连字符。为了避免误报：

- 回答因 `max_tokens` 被截断（推理模型把预算用光）或为空时，判为**无法判定**，而不是截断；
- 漏掉口令时会换一组新口令复测。截断会在同一深度重复出现，偶然的回忆失误不会。只有同一深度两次都漏才判为**不一致**。

官方 gpt-6-luna 在 2k、32k、100k 处全部找回（计费 2,181、33,487、104,474 input token）。

## 7. 局限：relaycheck 测不出什么

- **大部分时间给真货的中转。** 真货比例 ≥ 80% 时，24 次采样通常抓不到（w = 0.8 时判为不一致的概率为 7.8%，见 §5.2）。只在高峰期换、只对长请求或贵请求换的中转同样难抓。请加大 `--samples`、在不同时间重复检测，并把单次通过视为弱证据。
- **会自适应的对手。** 探针和计费提示是公开且固定的，能识别它们的中转可以只把这些请求转给真模型。随机化探针措辞会牺牲校准，这是后续工作。
- **厂商更新与漂移。** 厂商可能在同一个名字下更新模型，这时**官方**端点也会被标出来。请用可信端点重新生成参考，并留意参考的生成日期。在约 1 小时的实验里没有观察到漂移，但我们没有测过几天或几周尺度上的漂移。
- **同家族、同权重的变体。** 相近的快照、量化版和轻度微调可能落在参考的抽样误差之内。通过的意思是“在这个样本量下区分不出来”，不是“权重完全相同”。
- **采样设置。** reasoning effort、系统提示、默认温度与参考不同，都会改变回答分布。relaycheck 会对看得见的设置给出提示，但中转可以改看不见的默认值。
- **校准范围。** 真实误报数字只来自一个模型（gpt-6-luna）、一种协议（Responses）、一小时、20 次运行。模拟表明，在多项分布和中等过离散下误报率符合名义水平。离散度更大或随时间变化的真实端点会提高误报；0.001 的不一致阈值留有余量。
- **计费。** 精确基准能把固定隐藏提示抓到几个 token 的精度，但只对与参考同模型、同协议、同提示的请求有效。中转可以只在长请求或带工具的请求里注入，也可以计费老实但做别的手脚。缓存检查依赖上游尽力而为的缓存。
- **上下文。** 32k/100k 各三根针无法定位精确的窗口大小；中转也可以只截断 100k 以上的内容。
- 自报身份、知识截止日期和 `model` 字段都很容易伪造，从不作为证据。
- **采样行为几乎相同的兄弟模型。** 2026-10-31 实测，拿 gpt-6.1-sol 冒充 gpt-6-astra 判为一致（p = 0.024）。两份参考的平均 JS 只差 0.017（两次官方自测之间的噪声是 0.01–0.025），即使 100 对 100 次采样，未做离散校正时也只有 p ≈ 3·10⁻⁴。各参考之间的距离可用 `npx vite-node scripts/compare-refs.ts refs/*.json` 查看。要分开这类模型需要别的信号（能力型或延迟探针），relaycheck 目前还没有。

## 复现

除 API 运行外都免费，且都不在 `npm test` 里（`npm test` 只用 mock）。

```bash
npm install && npm run build && npm test

# 真实 API（OpenAI key 放在 RELAY_KEY）；费用按 gpt-6-luna 价格估算
RELAY_KEY=... node dist/cli.js fingerprint https://api.openai.com --model gpt-6-luna --api responses \
  --reasoning-effort none --samples 100 --out refs/gpt-6-luna.json          # 2,416 次请求，约 $0.015
RELAY_KEY=... npx vite-node scripts/collect.ts -- fpr gpt-6-luna 480 current 24 24   # 11,520 次请求，约 $0.07
RELAY_KEY=... npx vite-node scripts/collect.ts -- power gpt-5.6-luna 240 current 24 16
npx vite-node scripts/analyze-real.ts -- --ref refs/gpt-6-luna.json --raw calib/raw/fpr-gpt-6-luna.jsonl
npx vite-node scripts/drift.ts -- --raw calib/raw/fpr-gpt-6-luna.jsonl          # 离散度与漂移诊断
npx vite-node scripts/set-dispersion.ts -- --ref refs/gpt-6-luna.json --raw calib/raw/fpr-gpt-6-luna.jsonl --write

# 模拟（不调用 API）
sh scripts/sim-batch.sh; sh scripts/sim-batch2.sh; sh scripts/sim-batch3.sh; python3 scripts/summarize-sim.py

# 端到端：故意不老实的本地中转
NODE_USE_ENV_PROXY=1 node scripts/dishonest-proxy.mjs --port 18990 --swap-to gpt-5.6-luna &
RELAY_KEY=... node dist/cli.js http://127.0.0.1:18990 --model gpt-6-luna --api responses --reasoning-effort none
```

原始回答（`calib/raw/*.jsonl`）保留模型原文，可以离线免费重新做答案归一化。
